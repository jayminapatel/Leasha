LeashaTechnical reference - app v0.3.3

    Leasha Technical Reference

    How Leasha is built: its layers and processes, the data it keeps, how a file becomes searchable, how a search is answered, and every command-line entry point.

    App v1.0.0 · schema v35 · Reference updated 8 October 2026 · Checked against main at 0a39a5e

    1Overview

    Leasha is a Windows desktop application that searches about 100 GB of local files and Outlook mail from a plain-English description. It is single-user and fully offline. Keyword search (SQLite FTS5, BM25) and meaning-based search (LanceDB vectors from a local ONNX embedding model) run together and are fused with reciprocal rank fusion. There are no services and no accounts; the only port is the optional, keyed MCP server on 127.0.0.1 for local AI programs, off until it is started.

    Runtime

    Python 3.12, PySide6 6.11.0 (Qt's own binding, LGPL-3.0), onnxruntime 1.24.4 (DirectML on Windows when a graphics adapter is present).

    Stores

    SQLite in WAL mode with FTS5 is the authority. LanceDB holds vectors and is always rebuildable from SQLite.

    Models

    Embedding BAAI/bge-small-en-v1.5 (384-d, FastEmbed); rerank Xenova/ms-marco-MiniLM-L-6-v2; CLIP ViT-B-32; RapidOCR; Florence-2, Whisper and a Qwen 2.5 chat model on ONNX Runtime.

    Size

    About 1,040 tracked Python files; 509 unit-test modules; 13,721 tests passed, none failed, on the laptop's last full run (8 October 2026, the whole-codebase review, on top of c795766).

    The twelve non-negotiables

    From docs/PROJECT_INSTRUCTIONS.md. They are design constraints, not preferences.

    1. No service in the search hot path: search works with Ollama stopped.
    2. Every error states what happened and how to fix it. A structured AppError, never a bare traceback or a silent except: pass.
    3. One bad file never halts a 100 GB run. SKIP_CONTINUE is expected in the thousands.
    4. Everything long-running is resumable; the cursor is persisted before it is needed.
    5. The UI thread never does I/O. Work goes to a QThreadPool worker and returns by signal.
    6. SQLite is the authority; LanceDB is derived and rebuildable from chunks.
    7. Every .ps1 is ASCII-only and saved UTF-8 with a BOM.
    8. Every layer ships a CLI entry point before it ships UI.
    9. Measure, do not assume.
    10. Read-only against user data. The indexer never modifies, moves or deletes.
    11. Anything tunable has a UI, or is not tunable. .env is written by the app.
    12. A library where one exists; an external converter only where none does, with the reason in CONVERTER_JUSTIFIED.

    3Layers and import rules

    • Downward only. app/ui/ may call the layers below it; nothing below may import from app/ui/. The deliberate exception is the Qt-free app.ui.presenter, which app/cli and app/shell import so the terminal and the window say the same words.
    • Ask the store. When the window needs something from the store, the accessor is added to the store; no view reaches around a layer.
    • No model in retrieval. Nothing under app/search/ imports app.llm except translate.py, and SearchEngine.search() cannot reach it (static test). The engine cannot reach git either (test_the_index_search_engine_cannot_reach_git_even_indirectly).
    • Platform isolation. Every Windows-only call lives in app/core/osbridge/ (test_no_windows_only_call_outside_osbridge).
    • Chat is Qt-free and never imports app.ui (test_chat_layering.py).

    Contracts between layers: settings through app/core/settings_registry.py (the backend declares, the UI consumes); results through SearchResult and SearchResponse in app/search/engine.py; errors through AppError (the UI never parses message text); progress as Qt signals carrying plain data.

    4Processes and threads

    UnitDetail
    Single-instance locksWindows named mutexes through ctypes (POSIX fallback). Local.KnowledgeGraph.V2.SingleInstance allows one window; Local.KnowledgeGraph.V2.IndexRun allows one writer, taken by app.cli index, reembed, watch batches and the window's own run. The mutex is the authority; the record in index_state only describes it. A new window waits up to 12 s for a closing one (app/core/run_lock.py).
    Separate indexerapp/index/child_run.py. The window starts -m app.cli index --events jsonl through app.core.osbridge.stdio.own_python(): sys.executable from source, leasha-cli.exe in a packaged build (where sys.executable is Leasha.exe, which only opens the window). Reader processes are started the same way. One JSON event per line on stdout (run_events.py); stdin carries pause, resume and stop, and a closed stdin means stop. Read by a blocking readline on the page's IndexWorker thread. The child runs below normal priority.
    Reader processesapp/index/read_process.py. Only pure-parsing readers (PROCESS_READERS) go out of process; OCR, picture models, LibreOffice, Outlook, media and zip stay in. A crash becomes ERR_READER_PROCESS_ENDED for that file and a fresh child. A file's clock starts when its reader is ready (START_LIMIT_S, ERR_READER_PROCESS_START).
    Folder watchapp/index/folder_watch.py: NativeSource (ReadDirectoryChangesW via osbridge/dirwatch.py) or PollingSource; ChangeBuffer debounces; BatchIndexer reuses the pipeline's per-file path ("There is no second indexer"). An overflow rescans that folder. Batches wait while the run lock is held. PST/OST and Archive roots are excluded.
    Removing a folderapp/index/forget_folder.py. Remove in Settings counts, asks, then deletes under the index run lock everything the folder brought in: rows at or under it, messages whose messages.store_path is under it (a message is stored as pst://<mailbox>/<entry>, not under the folder) and their attachments - text vectors, picture vectors, then SQLite, in batches of 2,000 - and drops the folder's archive record. A row also under a folder still listed stays. file_ids_outside finds rows from no listed folder; Settings shows the count under the list with a button to remove them. The clean-up after a run uses the same lookup, so a .pst deleted from disk takes its mail with it.
    Mail archivesapp/ui/widgets/mail_archives_box.py, filled from SqliteStore.mail_archives() (every .pst/.ost row with its message count by messages.store_path). A per-archive reader choice is saved as JSON under ui:pst_backends (run_setup.load_pst_backends/dump_pst_backends, keys archives.normalise(path), "auto" dropped) and applied by apply_saved_pst_backend at the start of every run as PstExtractor.backends; backend_for(path) falls back to the global ui:pst_backend. Read again is the forced single-file run (_index_file_now): no read stamps, no resume cursor. Clear and read again deletes the archive's rows with forget_folder.forget_ids first.
    Pipeline threadsA bounded priority queue fed by the walker; N extraction workers (default max(1, min(4, cores // 2))); one consumer writing SQLite; one feeder thread embedding and writing LanceDB. Indexer threads lower their own priority to THREAD_PRIORITY_LOWEST.
    GPU gateapp/core/gpu_serialize.py: one process-wide lock around DirectML session build and inference. After a transient driver error (for example 887A0005) it latches "GPU unreliable" and later work runs on the processor; a failed batch is redone on the processor.
    Governorapp/index/resources.py ResourceGovernor, with a pure verdict(snapshot, limits), in order: free disk below MIN_FREE_GB stops the run (the only stop); memory growth above INDEX_MEMORY_MB pauses; on battery pauses (INDEX_PAUSE_ON_BATTERY); CPU used by other programs above INDEX_CPU_PERCENT for 5 s pauses, resuming after 10 s quiet. Leasha's own children are subtracted. Asked at most every 0.25 s; the process table is walked at most once a second. The person's Pause is seen on every file.
    SchedulerPure due_at for manual / startup / interval / daily (app/index/schedule.py), driven by a Qt timer (app/ui/scheduler.py).

    5Data: where it lives and what it holds

    Paths and .env

    .env sits in the project folder (project_root(); in a packaged build that is the _internal folder of the install), is written by the installer and by the window, and is never committed. Only DATA_PATH, PROJECT_PATH and LOG_PATH are pinned.     LanceDB (VECTOR_PATH)

    TableHolds
    chunkschunk_id, file_id, 384-d float32 vector, ext, mtime_ns. Cosine.

    An IVF_PQ index is built only past 100,000 rows (flat scan below), with √rows partitions capped at 4,096. Compaction every 50,000 rows; old versions kept one hour. Reads use read_consistency_interval=0, so a window opened before a run sees a vector table created after it (median 216 ms vs 219 ms over 30 searches on 87,216 rows). If LanceDB and SQLite disagree, SQLite wins and leasha reembed rebuilds the vectors from chunks.

    6Indexing: from a file to a searchable passage

    1. Walk (walker.py). Change detection is two-tier: mtime_ns and size from stat(), then the blake2b hash only if those moved. A .pst is never hashed, and Outlook moves the date of every archive it mounts, so Pipeline._classify asks the reader for a change marker (extract.base.change_marker) and lets it overrule the date in both directions; an interrupted archive's folder cursor is kept while the marker still matches. With no marker (an archive Outlook holds open, a row written before markers existed) the date and size decide. Exclusions prune during the walk. A root may be one file: walker.walk walks it as a listing of its own folder that names only it, so every rule applies as inside a folder; scan counts it as one file; archives.files_under says a file is under itself; folder_watch.live_roots leaves it out. Cloud placeholders are recognised from the same stat. Archive roots are walked once and re-walked only on their interval, a rescan, an incomplete pass, or a changed top-level mtime. With INDEX_ORDER=newest everything is found first, then "read first" folders, then the rest newest first.
    2. Queue and govern. Bounded queues give back-pressure; the governor pauses with a reason sentence.
    3. Extract (app/extract/base.py REGISTRY, loaded lazily). Each reader is a library first; external converters only where no library exists (config/extractors.toml).
    4. Chunk (chunker.py): about 512 tokens with 64 overlap, preferring paragraph then sentence boundaries.
    5. Write SQLite in groups of up to 256 documents or 0.1 s, checkpointing every 50 files or 2 s.
    6. Embed on the feeder thread: FastEmbed on ONNX Runtime, L2-normalised, batched (EMBED_BATCH), repeated text embedded once (EMBED_DEDUP). The device comes from EMBED_DEVICE (auto, cpu, gpu). With INDEX_TWO_PHASE on, a file is PARTIAL (keyword-searchable) until its vectors land, then INDEXED, and reading never waits for the model: a batch the model is too busy to take is parked as chunk ids (the text stays in SQLite), and the model works through the parked batches whenever it is free, then in a last "meaning" phase at the end of the run. An unchanged PARTIAL file is not read again; every run starts by parking the passages still at embedded = 0, whole files per batch (unembedded_by_file). Embedding is the run's cost: on the owner's 15-hour run it was 54,555 s against 1,568 s of SQLite writes, at about 8 passages a second on the processor (4 threads; 8 threads gained 6%, the Iris Xe graphics card was slower). Spreadsheet types (KEYWORD_ONLY_EXTS: xlsx, xlsm, xlsb, xls, ods, csv, tsv) are found by their words only unless INDEX_SPREADSHEET_MEANING is on: their passages are written with embedded = 2, the file is INDEXED at once, and coverage figures leave them out.

    Resumability. The files table is the mechanism: a re-walk costs one stat() per unchanged file. mbox resumes per message, PST per folder (persisted every 30 s), transcripts through a journal. The index_state cursor is progress reporting only.

    Mail and attachments

    • PST/OST (email_pst.py, pst_libpff.py): choose_backend() picks Outlook MAPI over COM or libpff. .ost always goes through Outlook. The setting is "How to read archives" (automatic, direct, Outlook). An archive Outlook has attached is locked, not damaged.
    • mbox and Takeout (email_mbox.py): lazy iteration, per-message resume; a Takeout zip goes through the archive reader and the mbox reader.
    • MAIL_ATTACHMENTS (mail_attachments.py): names, documents (default), pictures, everything. Under documents, Word, Excel, PowerPoint, PDF, text, CSV and HTML are read for contents; a zip gives its name and its members' names; everything else, pictures included, is name only and never OCR'd. Inline pictures get no row. Attachment rows are keyed <message>/attachments/<name>.
    • An attachment's own type and size. pipeline._row_type_and_size gives an attachment's row its own ext and size_bytes (meta['attachment_name'], meta['attachment_size'] from email_pst._attachment_documents); a zip member's member_size (set by archive._read_one) is preferred over an attachment's. Schemas 31 and 33 repaired rows written before: type from the key, size blanked until the archive is read again.
    • Open from a copy (ui/attachment_open.py). An attachment or a zip member opens from a read-only copy in <CACHE_PATH>\opened, swept per session and cleared on close. Mail bytes come from extract/pst_attachment.read_attachment (libpff, found by messages.folder_path / folder_index, the message number checked, a search as fallback); zip bytes from member_of, nested, reading a zip on disk by path. The route is presenter/opening.plan_for and tasks.open_target through workers.open_row_async; the worker body that writes the copy is tasks.save_attachment_copy. Error: ERR_ATTACHMENT_OPEN. The preview draws an attachment's or zip member's PDF, picture or .xlsx grid from memory (preview_loader.in_memory_preview, attachment_open.bytes_of, read_attachment(search=False, max_bytes=)).

    Images, OCR, photos and speech

    • OCR ladder (ocr_ladder.py): rung 0 metadata (free); rung 1 a 256 px thumbnail check (about 5 ms) against OCR_WHITE_PAGE_PERCENT; rung 2 a detection probe; rung 3 full RapidOCR (about 3.6 s a page). INDEX_OCR_PASS runs it with the run, after it, or only when asked.
    • Photos: Florence-2 tags and captions on ONNX Runtime (app/ort/florence.py), labelled as AI descriptions and stored in file_tags; a CLIP picture lane in image_vectors; perceptual hash for near-duplicates; EXIF taken-at date; offline place names; face piles with insightface (optional, off).
    • Speech and video: Whisper on ONNX Runtime (app/ort/whisper.py), audio decoded with PyAV; video keyframes by interval and cap. Media work is queued (ERR_MEDIA_BACKLOG) and drained at the end of a run.

    7Search: from a sentence to a ranked list

    1. One reading for every tab (app/ui/tasks.py::read_box): commands.expand_slashes turns /type pdf into type:pdf; translate_rules recognises names, dates and kinds as chips (a name becomes from: only if that sender exists, a noun becomes type: only if the extension exists); then parse_query. Chips never rewrite the typed text.
    2. Parse (query.py): phrases, -exclusions, prefix*, OR/AND/NOT, relative dates; to_fts_match() cannot produce a malformed FTS expression. Limits: 4,096 characters, 64 terms; scopes all, mail, documents, code. Kind words such as type:excel expand through _EXT_GROUPS, which a test keeps identical to the /type menu. *.ext is read as a type filter (_STAR_EXT).
    3. Two tiers. interim(): BM25 only, 20 rows, after 150 ms of stillness, never cached or logged. search(): the full tier after 400 ms or Enter.
    4. Full tier: wildcard expansion through chunks_vocab; pasted error messages become phrase searches; spelling correction for words the index has never seen; keyword, vector and CLIP retrievers in parallel; RRF fusion; optional cross-encoder rerank (never fails a search); recency blend (weight 0.03, half-life 180 days); relax-on-empty (labelled); version folding by perceptual and content hash; notices.
    5. Interpret (translate.py, L8a): an optional local model rewrites a sentence into operators, shown and editable, before the search. Time limit 45 s. Retrieval itself never calls a model.
    6. Per-page policy (policy.py): Code turns off spelling, relaxing, recency and folding; Files turns off folding.
    7. Code tab: in-index definitions then mentions (code_search.py); git history through gitquery.py (builds argv) and gitsearch.py (runs it; 2,000 rows, 120 s, two repositories at a time). git log -S took 1.59 s over 75 commits against 0.33 s for git grep, so history search is an explicit, cancellable action. Git is started as mingw64\bin\git.exe directly so Stop really ends it.

    8Chat and the local models

    • Router (app/chat/router.py): rules first, a small model only when the rules cannot decide. Classes: LOOKUP, AGGREGATE (an SQL count), SYNTHESIS, FIND (the answer is the result list), ABSENCE, FOLLOWUP, CHAT (social turns only). A general question still searches first. A sentence that names a value written in a document (VALUE_NOUNS, and phrases such as "passport number", "sort code", "expiry date") is LOOKUP whatever verb it opens with ("find the passport number"), read and quoted rather than listed; "find my passport" names a document and stays FIND.
    • Engine (engine.py): route, plan, search (at most 3 rounds), assess, answer. The answer streams; reconcile.py and verify.py drop unsupported claims (strictness 70 by default). Quotes must be verbatim; numbers, dates and names are checked exactly. With no model, counts, finds and absence questions still work.
    • Engine choice (app/llm/engines.py): CHAT_ENGINE=onnx (default; app/ort/llm.py::OnnxLLM, one per process) or ollama. The same choice covers Chat, Interpret and Describe, and a change in Settings applies at once (settings_controller._apply_engine_change).
    • Web (web.py): CHAT_WEB_ENABLED is off by default. Local retrieval runs first; only a sanitised keyword query of ten words or fewer leaves the machine; SSRF guard, three redirects, 1 MB cap; ask-first and show-query on.

    12Command-line reference

    Launchers

    • leasha.cmd works from its own folder. With no arguments, or --debug, it opens the window (pythonw -m app.main, detached). Anything else runs python -m app.cli … and keeps its exit code, so leasha stats is python -m app.cli stats. Without a venv it says "Leasha is not installed yet. Run run-install.cmd first."
    • A packaged build has two programs in its install folder: Leasha.exe opens the window (no console); leasha-cli.exe is the console program, which runs -m module, -c code and script paths the way python.exe does, and takes plain app.cli commands (leasha-cli stats).
    • app/main.py: --debug records the session to logs\sessions\; other arguments go to Qt.
    • Global options on every command, before or after it: --env ENV (an alternative .env) and --json (machine-readable output). --version prints Leasha <VERSION>. Every run writes logs\runs\run-<stamp>-<command>.log and prints its path only on failure.
    Exit codeMeaning
    0success
    1an AppError, a command reporting failure or no result, or Ctrl+C
    2ERR_NOT_IMPLEMENTED, or an argparse usage error

    Finding things

    search

    leasha search [--limit N] [--no-rerank] [query ...]

    query takes the same grammar as the box: type: after: before: path: from:, "phrases", -exclusions and slash forms such as /newest. --limit defaults to 20; --no-rerank skips the cross-encoder. Exits 1 when there are no results, the query is empty, or there is no index. Read-only.

    leasha search the safety report Dave sent about Leeds /after 2024

    files

    leasha files [--limit N] [--type EXT] [name ...]

    Part of a filename or folder name; --limit 50 by default; --type pdf,docx. Exit 0 even when nothing matches.

    commands

    leasha commands [--git]

    The filter catalogue; --git lists the repository switches instead.

    shell

    An interactive search prompt with a dropdown, over the same presenter as the window. Ctrl+D leaves.

    gitsearch

    leasha gitsearch [--repo PATH] [--every-repo] [--show SHA] [--depth N] [--limit N]
                 [--timeout S] [--measure] [--rev EXPR] [--depths N,N] pattern

    pattern takes / switches ("CustomerId /history /extension cs"). Depth and limit default to 2,000, timeout to 120 s. --every-repo searches every known repository two at a time; --show prints one commit with its diff; --measure times history search at several depths.

    repos

    leasha repos [--scan PATH ...] [--forget ROOT] [--remember ROOT]

    Lists repositories. --scan reports what a run would find without indexing; --forget stops treating a folder as a repository (nothing deleted or re-indexed); --remember undoes it.

    timeline

    leasha timeline [--year YYYY] [--month YYYY-MM] [--after DATE] [--before DATE]
                [--kind KIND] [--limit N] [--cursor CURSOR] [--no-fold]

    Kinds: everything (not code), photos, videos, documents, mail, code. 200 items a page; --cursor continues. With no dates it says what there is.

    report

    leasha report [--out FILE] [--exclude NAME,NAME] {inheritance|space}

    Also accepts digital-inheritance and space-report. Writes only the --out file.

    Windows installer

    packaging\build.ps1 builds it in one command (-Release also copies it to the Google Drive Releases folder). packaging\leasha.spec is a one-folder PyInstaller 6.22.3 build with two programs, Leasha.exe and leasha-cli.exe (see Launchers), entered through packaging\leasha_entry.py. packaging\installer.iss (Inno Setup 6) installs per user by default, with no administrator needed; asks where the index goes (default %LOCALAPPDATA%\Leasha\Data); writes <install>\_internal\.env only when none exists; offers two tasks, downloading the search models and installing LibreOffice through winget; and offers to run doctor.py --quick at the end. Uninstalling leaves the index.

    13Testing

    14Versions, documents and releases

    • VERSION (1.0.0) is the only place the version lives; app.core.version.build_info() adds git describe. MAJOR: an index change that cannot be migrated. MINOR: a build-spec layer complete. PATCH: fixes and tuning.
    • Schema version is its own integer (34), stepped one migration at a time.
    • Every .md opens with an H1 and the line **Doc version:** X.Y · **Updated:** YYYY-MM-DD · **Applies to:** app vX.Y.Z; test_docs_versioned.py fails the suite otherwise, with no exemption list. HANDOFF.md and docs/PROJECT_INSTRUCTIONS.md must state the current version (test_handoff_current.py).
    • Where things live: code and documents on GitHub jayminapatel/Leasha, branch main; release builds outside the repository under Leasha\Releases\<version>\ on Google Drive; the owner's index never in git.
    • Release checklist (docs/VERSIONING.md): acceptance tests pass, doctor READY, budget re-measured, VERSION bumped, document headers bumped, HANDOFF updated, CHANGELOG promoted, then chore(release): vX.Y.Z and a tag.
