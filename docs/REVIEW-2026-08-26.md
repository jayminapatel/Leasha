# Comprehensive review

**Doc version:** 1.0 · **Updated:** 2026-08-26 · **Applies to:** app v0.3.2

Five parallel review passes: verification of the 2026-08-25 review, storage + indexing,
search, UI, and extraction/core/CLI/tests. Every finding was verified against the current
code with `file:line` evidence before publication. Line numbers are from today's tree.

---

## Verdict

**The team that fixed yesterday's review did excellent work — and the codebase has moved
from "integration failures" to "scale failures".** Of the 42 findings across
`REVIEW-2026-08-25.md` and `CODE_REVIEW.md`: **23 fixed, 8 partially fixed, 11 still live.**
Every UI defect and every P1 data-safety defect was fixed, usually with the review's own
wording quoted in a comment and a pinning test beside it. That discipline is rare and worth
naming.

What remains, and what this review adds, clusters in three themes:

1. **The cache still does not exist.** Yesterday's single most-emphasised finding is
   untouched: no cache class exists anywhere in `app/`, `cache=` is passed at none of the
   four `SearchEngine` constructions, and `_cache_key`/`_cache_get` remain dead code.
   There is still no warm search, and P12/P13 (generation bumps, usage-log writes per
   search) remain moot-but-live behind it.
2. **Several end-of-run and edge paths have never been exercised at target row counts.**
   The mechanisms are excellent; the paths that only matter at 20–30M chunks (re-extraction
   of skipped files, prune N+1, migration v10's index loss, the v7 backfill OOM) are where
   this review's HIGHs live.
3. **The codebase keeps breaking its own rules in new code.** "Never block the UI thread"
   is enforced by test — and violated in five places written since. "One lookup for
   converters" was fixed for reporting and not for execution. The rule-setting is
   world-class; the rule-keeping needs the same wiring-test treatment yesterday's review
   prescribed.

Nothing found today destroys committed data. The write-ordering contracts are sound.

## New findings — Critical and High

### H1 — Every skipped/failed file is re-extracted on every run
`app/index/pipeline.py:1252`. `_classify` returns `UNCHANGED` only for `status == INDEXED`.
A SKIPPED row with identical mtime/size falls through, is re-queued, fully re-parsed, fails
again, and is rewritten — every incremental pass, forever. 100k scanned PDFs recorded as
`ERR_NO_TEXT_LAYER` means every nightly run re-pays hours to rediscover known failures. It
also makes `retry_locked` (pipeline.py:1143) redundant, which is evidence the fall-through
is unintended. **Fix:** treat unchanged SKIPPED/FAILED as settled except an allow-list of
retryable codes (`ERR_FILE_LOCKED`, OCR-mode-changed).

### H2 — Migration v10 permanently drops two indexes
`app/storage/migrations.py:516-525`. The `files` rebuild recreates six indexes but not
`idx_files_mtime` or `idx_files_source_kind` — the very index v5 documents as the
6.30ms→0.04ms fix. Any database migrated through v10 loses "newest first", `after:`/
`before:` and `repo_files` performance permanently; fresh databases skip the rebuild, so
tests never see it. **Fix:** add the two `CREATE INDEX` statements to v10 *and* ship a v13
`IF NOT EXISTS` repair + `ANALYZE` for already-migrated indexes.

### H3 — Migration v7 materialises the whole corpus in RAM
`app/storage/migrations.py:295-304`. `SELECT id, text FROM chunks ... .fetchall()` during
`connect()` — tens of GB at 20–30M chunks; the upgrade OOMs before the app opens, no
backup, no progress. **Fix:** keyset pagination committing per batch, with logged progress.

### H4 — Embedder failure kills hybrid search instead of degrading
`app/search/vector.py:73-93`. `vector.search` re-raises `AppErrorException`;
`Embedder.embed` raises exactly that for a missing/broken model. The whole search fails and
already-computed keyword hits are discarded — contradicting the module's own contract and
the `NOTICE_NO_VECTORS` machinery built for exactly this. **Fix:** catch, log, return `[]`,
tag the response so the notice carries the cause.

### H5 — Filter searches materialise every eligible file id, serially
`app/search/keyword.py:158-172` + `engine.py:373`. Any filter — including the UI scope
chips — builds a Python set of all matching file ids before the parallel fan-out. At
target scale a "Documents" chip is a multi-million-entry set per search, on the calling
thread, delaying both retrievers. **Fix:** probe with `LIMIT MAX_PREFILTER_IDS+1` first;
store filterable columns in the Lance table for native pushdown; run the rest inside the
pool.

### H6 — BM25 scores every matching row before LIMIT
`app/search/keyword.py:71-84`. `MATCH ? ... ORDER BY score LIMIT ?` computes bm25 and the
joins for every match; with AND_TERM_LIMIT=1 turning multi-word queries into OR, a
two-common-word query touches millions of rows per keystroke at scale. This is the main
p95 risk. **Fix:** when unfiltered, use FTS5's dedicated `ORDER BY rank LIMIT` optimisation
in a rowid subquery, joining only survivors; when filtered, reuse the vector path's
over-fetch ladder. Benchmark at representative scale before trusting the 300ms budget.

### H7 — Prune is an N+1 that spawns a LanceDB version per file
`app/index/pipeline.py:1977-1979`. One `delete_by_file_ids([file_id])` (a new Lance
dataset version each) plus one full write transaction per deleted file. Deleting a
10k-file folder produces 10k Lance versions — the exact pathology `COMPACT_EVERY_ROWS`
exists to prevent. **Fix:** one chunked `delete_by_file_ids(doomed)`, SQLite deletes in
`store.batch()`.

### H8 — Deleted PSTs/archives are never pruned
`app/index/pipeline.py:1970-1976`. `_prune_missing` iterates `source_kind="file"` only;
no other deletion path exists for `archive`/`pst_message`/`eml` rows. Delete a 30GB `.pst`
and 200k messages stay searchable forever. **Fix:** detect missing archive paths in the
prune pass and cascade-delete `path LIKE archive_path || '#%'` plus vectors by file_id.

### H9 — Quadratic chunker, measured
`app/extract/chunker.py:141` (carried from yesterday, now quantified): 20k words = 4.2s,
80k words = 73s. A 1MB log/CSV spends minutes in chunking; 10MB effectively hangs the
worker. `base.py:129-137` already uses bisect; the chunker does not. **Fix:** sorted
`paragraph_starts` + `bisect_right` comparison — O(W log P) — plus a perf regression test
(100k words < 2s).

### H10 — `.doc` conversion is broken on Windows, the ship platform
`app/extract/converter.py:333` vs `:250`. `convert()` uses bare `shutil.which`, but
`resolve_binary()` exists precisely because LibreOffice never puts itself on PATH on
Windows (the module's own comment). Settings and doctor say "found, route enabled"; every
actual conversion raises `ERR_CONVERTER_MISSING`. The "two lookups, two answers" bug was
fixed for reporting only. **Fix:** `binary_path = resolve_binary(binary_name)` at :333,
plus a test patching `shutil.which` to None.

### H11 — Files tab blocks the UI thread on open/reveal
`app/ui/files_view.py:345,353` calls `open_in_explorer` inline — whose own docstring says
"Never call this on the UI thread" (network share = seconds of freeze). `:318-331` also
does a synchronous store read per double-click that is unnecessary: `FileRow.path` is
already on the row object. The shell fixed exactly this for search results; the Files tab
regressed it. **Fix:** route through `CallableWorker` like `shell._open_path`; read the
path from the row.

## New findings — Medium

- **M1** `engine.py:358-363` — the `closed` shutdown guard only runs when a cache is
  configured; with `cache=None` (i.e. always, today) a search in flight at close hits a
  shut-down executor: the thrice-reported crash the guard documents fixing. Hoist the
  check to the top of `search()`.
- **M2** `engine.py:619` — cache key lowercases the raw query, colliding `pump AND valve`
  with `pump and valve` (different semantics by design). Key on the un-lowered query or a
  canonical `ParsedQuery` serialisation. (Latent until the cache exists — fix it before
  wiring the cache, not after.)
- **M3** `engine.py:253-258` + `wildcards.py:236-243` — wildcard expansion cache is never
  invalidated by index writes; the comment's invariant is false. Include
  `store.generation` in the key.
- **M4** `query.py:75-79` — `-type:pdf` silently becomes a *positive* filter (user asked
  to exclude PDFs, got only PDFs); `-"phrase"` becomes a required phrase. Honour or report
  the negation.
- **M5** `engine.py:374-379` — no timeout on retrieval futures; a hung LanceDB scan blocks
  the 2-worker pool and every later search. `result(timeout=…)` + keyword-only degrade.
- **M6** `pipeline.py:1467-1615,1825` — archive marker is written INDEXED while up to 256
  of its messages sit in `pending_vectors`; a crash or embed failure leaves permanent
  silent holes in vector coverage that no path ever drains (`iter_unembedded` is only
  reached by manual `reembed`). Flush vectors before `_write_marker`; drain unembedded at
  run start.
- **M7** `pipeline.py:1755-1760` — `_store_message_meta` omits `"quoted_removed"` from its
  keys tuple, so the schema-v12 column is NULL for every new message and the mail-preview
  feature built on it can never show data. One-line fix.
- **M8** `vector_store.py:393-422` from `add():308` — a mid-batch IVF_PQ retrain runs
  synchronously on the consumer thread (tens of minutes at 6.4M/12.8M rows); bounded
  queues mean everything blocks and the UI reads as a hang, with no pause-reason signal.
  Keep only the end-of-run call, or set a "building index" reason on stats.
- **M9** `search_view.py:197-221` — clearing the search box never clears results: the
  empty-query branch of `_dispatch` is unreachable from typing (`tier_for("")` returns
  `Tier.NONE`). Esc leaves stale results and a status line lying about counts.
- **M10** `search_view.py:231` + `shell.py:1447` — every failed background search raises a
  modal QMessageBox, per debounced keystroke; a transiently locked DB produces a queue of
  modals. Route search-tier failures to the NoticeBar; reserve modals for user actions.
- **M11** `widgets/preview.py:371-401` — `QPixmap(path)` and `QPdfDocument.load` run in a
  UI-thread slot despite the docstring's promise; decode `QImage` on the worker.
- **M12** `search_bar.py:163-177` vs `shell.py:344,571` — two "Rerank" controls that never
  synchronise: toolbar checkbox (hard-coded True, unpersisted) and Settings checkbox
  (persisted). Untick Settings and the toolbar lies — the exact class of bug fixed
  yesterday. Initialise from stored state, connect both to one handler.
- **M13** `settings_view.py:288-332` — `count_searches()` and libpff import probes run on
  the UI thread during `MainWindow.__init__`, before staged background work starts.
- **M14** `config.py:299-303` — only keys already present in `.env` can be overridden from
  the environment; `RERANK_ENABLED=false` in the env does nothing otherwise,
  contradicting "environment variables win". Iterate a canonical key list.
- **M15** `ocr.py:118,215-232` — a transient engine-load failure latches `_engine_failed`
  forever and every image thereafter is recorded `ERR_NO_TEXT_LAYER` — a broken engine
  misdiagnosed as thousands of blank photographs. Raise `ERR_OCR_UNAVAILABLE` instead.
- **M16** `email_pst.py:281,297` — `list(folder.items())` materialises every message body
  in a folder at once (100k-message Inboxes are the target corpus); this is the memory
  profile that makes 30GB PST runs swap. Iterate lazily.
- **M17** `pipeline.py:622` + `walker.py:419` — three separate sets each hold every
  lowercased path for the run (~1GB each at 5M files). Share one set.
- **M18** `walker.py:484-487` — no `\\?\` long-path handling; on stock Windows any path
  >260 chars is silently skipped with no row, no skip, no count — the "invisible file"
  failure NAME_ONLY was built to eliminate. Count stat failures; probe the policy in
  doctor.
- **M19** `results_view.py:207-216` — the delegate migration dropped all text from the
  model: no DisplayRole, no AccessibleTextRole. Screen readers see N empty items. One
  line in `_append` fixes the primary results list for assistive tech.
- **M20** `filters.py:84-119` — LIKE parameters are lowercased but columns are not, and
  SQLite LIKE is ASCII-only case-insensitive: `from:josé` misses `José@…`, and the FTS
  half of the same search *does* fold it. Store lowercase shadow columns.

## What is genuinely world-class already

- **The extraction contract**: offset invariants enforced by construction, failure-as-a-
  value via AppError/SKIP_CONTINUE honoured across all 18 extractors, converter allow-list
  in code with `shell=False` everywhere, archive traversal refused not sanitised, zip
  bombs declined from the central directory.
- **Storage discipline**: per-thread connections over WAL with documented lock ordering,
  crash-ordering contracts reasoned in writing at the exact line they protect, FTS
  optimize gated on run size, LanceDB compaction with counted-not-queried rows.
- **UI threading hygiene as institutional memory**: `workers.py` documents each guard with
  the crash it was written for; presenter is Qt-free and held to it by tests; generation-
  stamping uniformly drops stale async results.
- **The test suite**: ~38k lines, 113 integration tests running the real CLI via
  subprocess, kill-at-50%-and-resume, disk-full injection, and a wiring-test category
  created in response to yesterday's review.
- **Privacy**: nothing phones home; `.env` never committed; diagnostics redact by
  allow-list.

## The pattern worth understanding this time

Yesterday's review found documentation substituting for verification. Today's finds
**rules substituting for enforcement**: "never block the UI thread" is tested for the
modules that existed when the test was written, and violated in five newer ones; the
converter's "one lookup" rule was fixed where it was reported, not where it executes; the
prune pass was hardened for files and never taught about archives. The fix is the same
instinct the team already showed with the wiring tests: when a rule is worth stating, it
is worth a test that fails when new code breaks it — a scanner that finds `QPixmap(`/
`store.` calls in view slots, a perf floor on chunking, a converter smoke test on the
platform that ships.
