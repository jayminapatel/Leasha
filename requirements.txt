# xlrd and striprtf are both pure-Python py3-none-any wheels, no compiler.
# Non-negotiable 12: they replace external converters, so .xls and .rtf are read
# on a machine with nothing else installed. Neither is exotic in a long archive.
#
# **xlrd 2.0 reads .xls only.** It dropped .xlsx deliberately, so it cannot
# collide with openpyxl - the split is by format, not by preference. Pinning
# below 2.0 to regain .xlsx would reintroduce the XML parsing that was removed
# for security reasons. Do not.
#
# .epub and .fb2 need no dependency at all: a zip of XHTML and a single XML
# document, both read by the standard library in app/extract/ebook.py. That
# removed pandoc from the project.
# Pure Python, py3-none-any wheel, no compiler. Reads DXF only: .dwg is AutoCAD's
# proprietary binary format with no open specification, and ezdxf does not read
# it - that route is the dwg2dxf converter in config/extractors.toml, shipped
# disabled. Without ezdxf, .dxf degrades to name-only rather than failing.
#
# extract-msg is the one exception to the wheel rule at the top of this file.
# It is itself a py3-none-any wheel, but its dependency `red-black-tree-mod`
# (<=1.23,>=1.20) publishes NO wheel at all - sdist only. It is two pure-Python
# files with no C sources, so pip builds it locally in seconds and no compiler
# is needed. Two consequences worth knowing:
#   * `pip download --only-binary :all:` fails on this tree. That is expected.
#   * A fully offline install needs the sdist cached, not just wheels.
# .msg support is optional: app/extract/email_files.py guards the import and
# raises a clear AppError if it is absent, so removing this line degrades .msg
# to "unsupported" rather than breaking the app.

# --- Optional: read .pst without Outlook -----------------------------------
# NOT installed by default, and deliberately not pinned above. libpff-python has
# no Windows wheel and compiles during install, which needs Build Tools for
# Visual Studio - exactly what the rule at the top of this file exists to avoid.
#
# Install it only if you want archives read without Outlook:
#     venv\Scripts\python.exe -m pip install libpff-python
#
# What it buys: no Outlook dependency, no COM, no file lock on the archive, no
# changes to your mail profile, and the whole PST path becomes testable. What it
# does not do: .ost (the live mailbox cache) still needs Outlook.
#
# The import is guarded everywhere, so its absence changes nothing.

#
# Run `doctor.py` to see which of these are active. Nothing here is required -
# every format is indexed by name and document properties without them.

#   vsdx==0.6.1
#       .vsdx shape text through a maintained library. NOT required: there is a
#       built-in reader that pulls the page XML straight out of the ZIP, which

#           venv\Scripts\python.exe -m pip install vsdx
#
#   mpxj + jpype1
#       .mpp / .mpt TASK LISTS - the only way to read Project files without
#       Microsoft Project installed. Deliberately not a dependency: mpxj bundles
#       32 JARs and needs a **Java runtime**, against this application's whole
#       premise of one process and no services. ~90MB plus a JRE.
#           venv\Scripts\python.exe -m pip install mpxj jpype1
#       and a JRE, e.g.:  winget install --id EclipseAdoptium.Temurin.21.JRE
#
#       Verified against mpxj 16.7.0, whose Java package is `org.mpxj`. It was
#       `net.sf.mpxj` before version 14 and both are tried, because assuming one
#       is how this silently read nothing on every modern install.
